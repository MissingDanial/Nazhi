# V2.1 第二批：任务恢复与本地保存

本轮面向个人和少量熟人试用。客户端与 bundled 后端一起升级，Room 数据库从 8 迁移到 9，保留原笔记、知识、问答和录音记录。新增 `local_ai_tasks`，只存请求身份、配置摘要、输入摘要和状态，不存 API Key 或登录 token。

## 恢复行为

| 中断位置 | 重开应用后的行为 |
| --- | --- |
| 已提交，尚未收到创建响应 | 按已保存的 requestId 查询原任务 |
| 已获得 taskId，尚未完成 | 查询原 taskId |
| 已完成，尚未本地保存 | 取回原结果，事务保存并标记 APPLIED |
| 本地已保存，重复结果/确认 | 返回原笔记或知识，不重复创建，不覆盖后续编辑 |
| 断网、查询超时 | 保留 WAITING 和输入，恢复网络后继续查询 |
| 后端重启或任务已过期 | 明确中断，保留输入，用户点击重试才创建新任务 |
| 切换账号或服务配置 | 等待切回原配置；不会向新账号自动上传旧输入 |
| 直连模型调用中断 | 保留笔记，标记中断，用户点击重试 |
| 整理期间修改原笔记或旧草稿 | 暂停应用结果，保留用户修改，提示重新整理 |
| 索引或问答中断 | 显示可重试状态，保留知识与问题，不自动再调用模型 |

浮窗录音自动保存为笔记；页面录音保存可编辑的预览，需要用户确认。关闭预览后可从对应日期的“待确认转写”继续。未确认或失败的录音不会在页面关闭时删除。音频文件清理在数据库提交后进行，删除失败留记录，下次启动补做。

## 实际进程中断验证

仅在独立、可丢弃的测试模拟器上运行。该场景会改测试 App 的服务配置并写入测试笔记。fixture server 只监听本机，不调用真实模型或录制音频。

```powershell
# 在一个终端启动 fixture，在另一个终端执行下列 adb 步骤
node app/src/androidTest/fixtures/recovery-server.mjs 8799

adb -s emulator-5556 shell am instrument -w -e class com.nazhi.app.core.repository.ProcessRecoveryScenarioTest -e recoveryPhase seed -e recoveryPort 8799 com.nazhi.app.test/androidx.test.runner.AndroidJUnitRunner
adb -s emulator-5556 shell am force-stop com.nazhi.app
adb -s emulator-5556 shell am start -n com.nazhi.app/.MainActivity
adb -s emulator-5556 shell am instrument -w -e class com.nazhi.app.core.repository.ProcessRecoveryScenarioTest -e recoveryPhase verify com.nazhi.app.test/androidx.test.runner.AndroidJUnitRunner
```

三个已接受任务分别模拟：创建响应未写入、完成结果尚未保存、处理时连接中断。验证重开后均保存一次，重复应用保留已编辑内容。访问 `http://127.0.0.1:8799/test/state` 检查每个任务仅有一次 POST，恢复只有 GET。常规仪器测试会跳过这个需要分阶段驱动的场景。

服务器持久化执行队列尚未实现；服务器重启后的自动续跑不在本轮承诺内。真实模型、实际麦克风和系统音频捕获另需设备与服务验收。
