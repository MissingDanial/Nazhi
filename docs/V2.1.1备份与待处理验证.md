# V2.1.1：备份恢复与跨日期待处理

第三批试用包版本为 2.1.1，安装版本号为 3。Room 仍为版本 9，不改变第二批的数据库迁移和服务器任务接口。面向文字收纳优先的个人与小范围试用。

## 备份行为

新备份格式 3 使用规范化 JSON 的 SHA-256 检测内容损坏；它不是数字签名，也不证明文件作者身份。格式 1/2 的有效历史备份可以导入，界面说明其没有完整性摘要。文件上限 32 MiB、10 万条记录，严格读取 UTF-8，检查重复字段、重复 ID、数据类型、日期、枚举、有限数值和关联关系。

| 场景 | 行为 |
| --- | --- |
| 导出后恢复到空数据库 | 保留文字、时间、来源、草稿、问答与引用；知识索引待用户手动重建 |
| 同 ID、内容相同 | 跳过，不新增副本 |
| 同 ID、本机已有不同内容 | 保留本机内容，预览显示冲突；新增且依赖该冲突记录的内容也跳过 |
| 预览后用户又编辑本机内容 | 在实际导入事务中重新计算冲突，不覆盖新编辑 |
| 文件损坏、关系缺失、重复字段 | 预览说明问题，禁止导入，数据库不写入 |
| 数据库写入失败或回读不一致 | 整次新增内容回滚，原记录保留 |
| 恢复未完成问答 | 保留原问题，立即显示可手动重试的状态，不自动调用模型 |
| 历史知识正文或来源已编辑 | 保留原问答摘录与历史来源，不重新审核旧答案 |
| 文件选择器期间重建界面 | 用暂存文件路径恢复，JSON 不放进 Activity 状态包 |
| 保存期间旋转 | 当前进程的短写入及核验继续，成功后记录备份时间 |
| 保存期间进程丢失 | 解除遗留忙碌，提示重新导出，不自动重写外部文件 |
| 保存位置只支持写入 | 显示已保存但未核验，持续提示用导入检查 |

备份包含 Note、KnowledgeEntry、知识草稿、ChatSession、ChatMessage 和 ChatCitation。已保存的音频转写文字属于 Note，会包含在笔记中；录音原文件、待确认转写预览、未完成 AI 任务身份、ReviewSession、向量、登录凭证、API Key 和后端配置不会包含。备份时间表示该次成功保存，内容截至时间表示快照生成时刻，不等于此后新增内容也已备份。

## 待处理行为

顶部入口保留原有四个底部页面，汇总跨日期的整理任务、待处理/失败知识和失败问答。普通未整理笔记与未确认草稿仍在对应日期。

- 查看列表或原文不创建模型调用。已完成或被新尝试替代的旧失败记录不继续显示。
- “继续查询”只查原请求；“重新处理/重试回答”明确确认会再次调用模型。
- 执行前重新检查状态与整理任务绑定，过期按钮不会从查询变成重新提交。
- 同项重复点击共享一次处理；离开页面不取消已经发起的处理。
- 整理重试前发现编辑过的待确认草稿，会先提示确认或跳过，保留用户修改。

## 荣耀 80 SE 与服务器升级准备

用户手机为荣耀 80 SE，后端运行于服务器；当前尚未提供手机系统版本、USB 连接和服务器启动方式/访问通道，因此本轮交付代码与模拟器验证，真实手机和服务器升级需接续验收。

1. 在原手机 App 导出现有数据，保留文件并先检查内容与记录数量。
2. 确认旧 App 与新包签名兼容，安装版本号允许覆盖；保留原签名发布升级包。不要通过卸载原 App 解决签名冲突。
3. 服务器使用本工作副本的 `nazhi-backend/`，核对 Node.js 22 以上、现有部署环境与启动方式，完成后端测试和新任务查询接口检查；备份真实环境配置，按原服务管理方式升级。
4. 手机填写服务器实际地址，依次验收分享/剪贴板/手动文字、整理、编辑草稿、确认知识、问答及备份恢复。索引和模型调用使用你选择的服务配置，实际厂商调用另需验收。
5. 在处理期间断网、切后台、重开 App，确认不重复保存；服务端任务丢失时保留文字并明确手动重试。服务器持久化执行队列仍未纳入本轮。
