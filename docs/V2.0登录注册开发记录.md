# V2.0 登录注册开发记录

**适用版本**：V2.0
**开发工作树**：`nazhi-android-v2.0`
**开始日期**：2026-06-06
**定位**：账号体系、登录注册、API 用户鉴权和设置页账号区

## 1. 版本目标

V2.0 的目标是把纳知从开发 token 鉴权推进到用户账号体系，让用户可以注册、登录、修改密码，并让后端 API 能识别当前用户。

V2.0 不做云同步，不做会员支付，不做微信登录、短信登录、多设备管理和复杂权限系统。

## 2. 基本原则

- Android 仍然保持本地优先：笔记、知识条目、向量和对话记录继续保存在本地。
- 登录用于建立用户身份、保护后端 API 和后续扩展额度/同步能力。
- 服务器资源按单机 `2核4G` 设计，避免引入重型组件。
- 核心用户数据进入 PostgreSQL，Redis 只保存短期状态、限流和缓存。
- 登录相关接口必须通过 HTTPS 暴露。
- 旧的 `NAZHI_DEV_TOKEN` 可在开发期保留为兼容路径，但 V2.0 新能力走用户 token。

## 3. 技术栈

### 后端

| 模块 | 选择 | 说明 |
| --- | --- | --- |
| Runtime | Node.js 20+ | 复用现有 `nazhi-backend` |
| Web 层 | 现有原生 HTTP/router | 当前接口规模较小，暂不迁移 Express/Nest |
| 数据库 | PostgreSQL | 用户、refresh token、登录日志 |
| 缓存 | Redis | 登录限流、短期 token 状态、黑名单 |
| DB Client | `pg` | 轻量 PostgreSQL 客户端 |
| Redis Client | `redis` | 官方 Redis 客户端 |
| 密码哈希 | `argon2` | 使用 Argon2id |
| Access Token | `jose` JWT | 短有效期，API 请求携带 |
| Refresh Token | 随机 opaque token | 只保存 hash，可废弃 |

### Android

| 模块 | 选择 | 说明 |
| --- | --- | --- |
| UI | Kotlin + Jetpack Compose | 延续现有架构 |
| 网络 | `NazhiBackendClient` | 增加 `/v2/auth/*` 方法 |
| 本地会话 | DataStore + `EncryptedSettingsStore` | access/refresh token 加密保存 |
| 页面入口 | 设置页账号区 + 首次启动登录态判断 | V2.0 先不新增底部 Tab |
| API 鉴权 | Authorization Bearer token | 优先使用用户 access token |

## 4. 后端接口

第一阶段新增：

```text
POST /v2/auth/register
POST /v2/auth/login
POST /v2/auth/refresh
POST /v2/auth/logout
POST /v2/auth/change-password
GET  /v2/auth/me
```

### POST /v2/auth/register

请求：

```json
{
  "email": "user@example.com",
  "username": "用户昵称",
  "password": "password"
}
```

响应：

```json
{
  "user": {
    "id": "uuid",
    "email": "user@example.com",
    "username": "用户昵称",
    "status": "active"
  },
  "accessToken": "...",
  "refreshToken": "...",
  "expiresIn": 900
}
```

### POST /v2/auth/login

请求：

```json
{
  "email": "user@example.com",
  "password": "password"
}
```

响应同注册。

### POST /v2/auth/refresh

请求：

```json
{
  "refreshToken": "..."
}
```

响应：

```json
{
  "accessToken": "...",
  "refreshToken": "...",
  "expiresIn": 900
}
```

### GET /v2/auth/me

请求头：

```http
Authorization: Bearer <accessToken>
```

响应：

```json
{
  "user": {
    "id": "uuid",
    "email": "user@example.com",
    "username": "用户昵称",
    "status": "active"
  }
}
```

### POST /v2/auth/change-password

请求头：

```http
Authorization: Bearer <accessToken>
```

请求：

```json
{
  "currentPassword": "old-password",
  "newPassword": "new-password"
}
```

成功后废弃该用户所有 refresh token，Android 清空本地会话并要求重新登录。

## 5. PostgreSQL Schema

建议使用独立 schema：

```sql
CREATE SCHEMA IF NOT EXISTS auth;
```

核心表：

```text
auth.users
- id uuid primary key
- email text unique not null
- username text not null
- password_hash text not null
- status text not null
- created_at timestamptz not null
- updated_at timestamptz not null
- last_login_at timestamptz

auth.refresh_tokens
- id uuid primary key
- user_id uuid not null references auth.users(id)
- token_hash text unique not null
- device_name text
- expires_at timestamptz not null
- revoked_at timestamptz
- created_at timestamptz not null

auth.login_events
- id uuid primary key
- user_id uuid references auth.users(id)
- email text
- ip text
- user_agent text
- success boolean not null
- reason text
- created_at timestamptz not null
```

## 6. Redis Key 约定

```text
rate_limit:auth:login:<ip>
rate_limit:auth:register:<ip>
auth:blacklist:access:<jti>
auth:refresh:user:<userId>
```

Redis 不保存核心用户数据。Redis 丢失不应导致用户表或 refresh token 表不可恢复。

## 8. 开发阶段

### 阶段 1：后端认证基础

- 增加 PostgreSQL / Redis / Argon2 / JWT 依赖声明。
- 增加数据库连接、Redis 连接和认证配置。
- 增加 auth migration。
- 实现 `/v2/auth/register`、`/v2/auth/login`、`/v2/auth/me`。

### 阶段 2：Android 登录注册 UI 骨架

- 增加 AuthSessionStore。
- 增加登录 / 注册 / 修改密码 Compose 页面。
- 设置页新增账号区。
- 登录成功后保存会话。

### 阶段 3：Token 生命周期

- 实现 refresh token 轮换。
- 401 后自动 refresh 并重试一次。
- 退出登录废弃 refresh token 并清空本地会话。

### 阶段 4：旧 API 鉴权迁移

- `/v1/*` 开发期继续支持 `NAZHI_DEV_TOKEN`。
- Android 纳知服务模式优先使用用户 access token。
- 后端记录用户维度调用日志，为后续额度/订阅打基础。

## 9. 验收标准

- 新用户可以用邮箱注册。
- 已注册用户可以用邮箱和密码登录。
- 登录成功后设置页显示用户名和邮箱。
- 用户可以在已登录状态修改密码。
- 修改密码后旧 refresh token 失效，需要重新登录。
- 退出登录后本地 token 清空。
- 未登录或 token 无效时，受保护 API 返回 401。
- 登录失败有基础限流。
- PostgreSQL 数据可以通过备份恢复。
- Android `:app:compileDebugKotlin` 和 `:app:assembleDebug` 通过。
- 后端 `npm run check` 和认证相关测试通过。

## 11. 仓库纳入记录

V2.0 登录注册同时涉及 Android 设置页、用户 token 存储、后端认证接口、PostgreSQL migration 和服务器部署配置，因此本阶段采用 monorepo 管理方式：后端作为 `nazhi-backend/` 一级目录纳入 Android 主仓。

纳入主仓的内容：

- `nazhi-backend/src/`：后端源码。
- `nazhi-backend/migrations/`：数据库 migration。
- `nazhi-backend/package.json` 和 `package-lock.json`：后端依赖声明。
- `nazhi-backend/.env.example`：环境变量模板。
- `nazhi-backend/README.md` 和 `API.md`：运行说明与接口文档。

不得提交的内容：

- `nazhi-backend/.env` 和其他真实环境变量文件。
- `nazhi-backend/node_modules/`。
- 本地接口密钥、临时 token、服务器密码、数据库真实密码。
- 本地工具缓存目录。

当前 `.gitignore` 已显式保护后端 `.env`、`node_modules/`、`.claude/` 和 `kyAPI.txt`。
